TL;DR — 30 秒版
  • Skill = 一个文件夹，含 SKILL.md（YAML frontmatter + 说明）+ 可选的脚本/资源。
  • 它把"如何完成特定任务"的专家知识封装成可复用的资源，让 AI 按需加载。
  • 关键设计是渐进式披露（progressive disclosure）：默认只加载 name/description，匹配后才加载全文。
  • 和 Prompt、MCP、Project 的区别：Skill 是任务级、可组合、按需加载。
  • WorkBuddy 中的项目级 Skill 保存在 .workbuddy/skills/<name>/SKILL.md，可被仓库内任何对话调用。

1. 这是什么

不同来源对 Skill 的定义一致，措辞各有侧重：

  • Anthropic（2025-10-16 发布的 Introducing Agent Skills）："Skills are folders that include instructions, scripts, and resources that Claude can load when needed." — 强调它是"按需加载"的资源包。
  • Anthropic Help Center："Skills are folders of instructions, scripts, and resources that Claude loads dynamically to improve performance on specialized tasks." — 强调动态加载是为了提升特定任务的表现。
  • Anthropic 中文官方文档：技能是"可复用的、基于文件系统的资源"，给智能体提供特定领域的专业知识（工作流、上下文、最佳实践）。

没有显著冲突，三个来源本质一致：Skill 是一个结构化的、按需加载的能力包。

3. 核心机制 / 组成

3.1 三层加载模型（Progressive Disclosure）

来自 Anthropic Cookbook 的官方说明：

  1. 元数据层（Metadata）：name（最多 64 字符）+ description（最多 1024 字符），从 SKILL.md 的 YAML frontmatter 读。AI 始终看到这一层。
  2. 完整指令层（Full Instructions）：SKILL.md 的正文内容，<5k token。AI 判断相关时才加载。
  3. 链接文件层（Linked Files）：SKILL.md 引用的脚本、模板、示例。只有真正用到时才加载。

它和别的组件怎么连：这种分层让"装 100 个 Skill"几乎不增加请求成本——大多数 Skill 只贡献 1 行 YAML。Anthropic 的数据：手动塞 8k token 的 Excel 说明 vs Skills 元数据 节省 98% 初始 token。

3.2 SKILL.md 的硬性结构

来自 Anthropic 中文官方文档的 Agent Skills 概述：

---
name: your-skill-name
description: 这个 Skill 做什么、何时使用
---

# 你的 Skill 名称

## 说明
[给 AI 的清晰、分步骤指引]

## 示例
[具体使用示例]

字段要求：

  • name：最多 64 字符；只能含小写字母、数字、连字符；不能含 XML 标签；不能含 "anthropic" / "claude"。
  • description：不能为空；最多 1024 字符；不能含 XML 标签；必须同时包含 Skill 的功能 + 何时使用。

类型来源示例谁触发

3.4 安全模型

同样来自 Anthropic 中文文档：

  • Skill 通过指令和代码赋予 AI 新能力，因此恶意 Skill 可能引导 AI 做未声明的操作。
  • 最佳实践：只使用可信来源的 Skill（自己创建的或来自 Anthropic 官方）。
  • 审查清单：检查所有捆绑文件（SKILL.md、脚本、图像、资源）；留意异常网络调用、文件访问模式、与声明不符的操作；从外部 URL 获取数据的 Skill 风险更高。

4. 一个具体应用场景

用 Skill 把公司报销流程教给 Claude（场景来自 Anthropic Help Center 的 Custom skills 例子）：

  • 谁在用：一家中型公司的财务团队。
  • 解决什么问题：员工每周问 Claude "怎么报销餐费"——需要统一答案，避免每次 Claude 重新编。
  • 怎么做的：把公司报销制度写进 expense-claim/SKILL.md，描述：什么场景调用（"用户问报销"）、如何计算金额上限、需要哪些附件。
  • 关键效果：员工问"500 元打车费能报销吗"，Claude 自动加载 Skill、按公司制度回答。

为什么这个例子可信：直接对应 Anthropic 官方文档列举的 Custom skills 典型场景（"Apply brand style guidelines"、"Generate communications following company email templates"、"Automate personal workflows"）。

5. 边界 & 容易混淆的点

容易混的概念区别
Skill vs Prompt Prompt 是单次对话的输入；Skill 是结构化的、可复用的资源，跨对话生效。
Skill vs Custom Instructions Custom Instructions 对所有对话生效（"你说话要礼貌"）；Skill 只在任务匹配时加载（"做 Excel 时遵循这个格式"）。
Skill vs Project Project 是"启动对话时一次性加载的背景知识"；Skill 是"按需加载的专用流程"。
Skill vs MCP（Model Context Protocol） MCP 让 Claude 连接外部服务和数据；Skill 教 Claude 如何使用这些工具。两者可叠加——MCP 给"能调用什么"，Skill 给"怎么调用"。
Skill vs Tool Tool 是单次 API 调用（get_weather）；Skill 是封装了多个工具 + 指令的"方法论"。

常见误区：

  • "Skill 越多越好"——错。每个 Skill 都对上下文窗口有少量开销（元数据 + description），堆太多反而稀释。
  • "Skill 等于提示词模板"——错。Skill 可以包含可执行代码（当传统编程比 token 生成更可靠时），不只文字。
  • "别人写的 Skill 直接用就行"——错。Skill 给 AI 新的指令 + 执行代码的能力，必须审查来源和内容。

8. 自测题

  1. Skill 的"渐进式披露（Progressive Disclosure）"三层分别是什么？
    💡 元数据层（name + description，AI 始终看到）→ 完整指令层（SKILL.md 正文，匹配时才加载）→ 链接文件层（脚本/模板，真正用到才加载）。
  2. SKILL.md 的 YAML frontmatter 里 name 和 description 各有什么硬性要求？
    💡 name 最多 64 字符、只能小写字母/数字/连字符；description 最多 1024 字符、不能为空，必须同时写清"功能 + 何时使用"。
  3. Skill 和 Prompt 的核心区别是什么？
    💡 Prompt 是单次对话的输入；Skill 是结构化、可复用、跨对话生效的资源包，还能包含可执行代码。
  4. Skill 和 MCP 是什么关系？
    💡 MCP 让 AI 连接外部服务和数据（给"能调用什么"）；Skill 教 AI 如何使用这些工具（给"怎么调用"）。两者可叠加使用。
  5. 为什么"别人写的 Skill 直接用就行"是危险的想法？
    💡 Skill 通过指令和代码赋予 AI 新能力，恶意 Skill 可能引导 AI 做未声明的操作。应只使用可信来源，并审查所有捆绑文件、网络调用和文件访问模式。
