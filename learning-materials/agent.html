1. 这是什么

"Agent"在 2024–2026 年的 AI 行业里被反复定义，不同来源各有侧重：

  • Anthropic（2024-12 发布，2025 持续更新）：Agent 是"LLM 动态指导自己的处理流程和工具使用，维持对如何完成任务的控制"的系统。这与"工作流"（LLM 和工具被预定义代码路径编排）形成对照。两者合称"agentic systems"。
  • OpenAI（2025-04 发布 A Practical Guide）：Agent 是"能代表用户独立完成任务的系统"，它用 LLM 管理工作流执行与决策，识别何时完成、主动纠错、失败时停止并交还控制权；并且能动态选择工具、在明确护栏（guardrails）内运行。

冲突点：OpenAI 的定义偏向"独立完成任务"，强调自主性；Anthropic 的定义偏向"动态控制流程"，强调与"工作流"的边界。两者在本质上是一致的——都强调 LLM 是决策中心、而不是被编排的零件。

3. 核心机制 / 组成

Anthropic 把 agentic systems 拆成一个由简到繁的阶梯。最底层是"增强型 LLM"（augmented LLM），上面叠工作流，再上面才是 Agent。

层级含义谁在控制典型例子
增强型 LLM 给 LLM 加上检索、工具、记忆 LLM 主动使用能力 能上网、能查日历的 ChatGPT
工作流 Workflow 预定义代码路径编排 LLM 和工具 代码 Prompt Chaining（先写大纲再写正文）、Routing（按问题类型走不同分支）
Agent LLM 动态决定下一步 LLM Claude Code、OpenAI Operator、Coinbase 的客服 Agent

OpenAI 把 Agent 拆成三个核心组件（更"原子"的视角）：

  1. 模型（Model）——做推理和决策的 LLM。越复杂的步骤越需要更强的模型；简单的检索/分类可以用小模型省钱。
  2. 工具（Tools）——Agent 与外部世界交互的接口。三类：数据类（查 DB、读 PDF、搜网页）、行动类（写记录、发消息）、编排类（Agent 调用其他 Agent）。
  3. 指令（Instructions）——定义 Agent 怎么行为。最佳实践：用现有文档改写、把任务拆小、明确每个动作、考虑边界情况。

关键连接：没有"循环退出条件"（loop exit condition），Agent 就不成立。一个常见的实现是 OpenAI Agents SDK 的 Runner.run()——它循环调用 LLM 直到满足下面任一条件：调用了最终输出工具、模型直接回复、或达到最大轮数。

5. 边界 & 容易混淆的点

容易混的概念区别
Agent vs ChatGPT ChatGPT 是被动应答；Agent 主动调用工具、循环执行、出错自纠。OpenAI 明确说"集成了 LLM 但不用它控制工作流的简单聊天机器人不是 Agent"。
Agent vs Workflow Workflow 是"程序员画好路线图，LLM 照着走"；Agent 是"LLM 自己看地图"。前者可控可预测，后者灵活但累积错误概率更高。
Agent vs Copilot Copilot 强调人机协作、每步由人确认；Agent 强调自主性、只在终点或卡死时打断人。
Agent vs RAG RAG 是"先检索再回答"的模式，常常作为 Agent 的一个工具出现；Agent 是更大的系统框架。RAG ≠ Agent。

什么时候不该用 Agent（来自 Anthropic）：

  • 规则能解决的：if-thelse 写得清楚的场景，用 Agent 是过度设计。
  • 延迟敏感、成本敏感：Agent 用更高的延迟和 token 换灵活性。
  • 单一调用 + 检索 + 示例 已经能搞定的：Anthropic 明确说"很多应用优化单次 LLM 调用就够了"。

8. 自测题

  1. Agent 和 ChatGPT 最本质的区别是什么？
    💡 ChatGPT 是被动应答（你问一句它答一句）；Agent 会主动调用工具、自主规划、循环执行直到任务完成，出错时还能自纠。
  2. OpenAI 把 Agent 拆成哪三个核心组件？
    💡 模型（Model）+ 工具（Tools）+ 指令（Instructions）。模型做推理决策，工具连接外部世界，指令定义行为边界。
  3. Anthropic 区分的"Workflow"和"Agent"关键差别在哪？
    💡 Workflow 是预定义代码路径编排 LLM 和工具（路线图是程序员画好的）；Agent 是 LLM 动态决定下一步（自己看地图）。
  4. 什么场景下不应该用 Agent？
    💡 规则能写清楚的（if-else 够用）、延迟/成本敏感的、单次 LLM 调用 + 检索 + 示例就能搞定的场景——上 Agent 反而是过度设计。
  5. Coinbase 客服 Agent 案例里，那个 99.99% 指的是什么？
    💡 客服系统的可用性（uptime）——每小时处理数千条消息的同时维持 99.99% 可用。数据来自 Anthropic 官方白皮书。
